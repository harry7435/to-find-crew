# game-manager → 서버 세션 로그인 마이그레이션 설계

## 배경

`/game-manager`는 로그인 없이 누구나 쓸 수 있는 localStorage 전용 도구이고, 이번에 만든
`/badminton/[id]`의 "게임 관리"(OrganizerBoard)는 로그인한 모임장만 서버에 저장하며 쓸 수 있다.
[board-persistence-design](2026-07-14-board-persistence-design.md) 작업을 실전 검증하는 과정에서,
`/game-manager`를 곧바로 제거하기보다 **"로그인 없이 체험 → 로그인하면 서버에 저장"** 흐름으로
포지셔닝하고, 이미 로컬에 입력해둔 선수 명단을 서버 세션으로 옮길 수 있게 해달라는 요청이 나왔다.

## 사용자 흐름

`/game-manager` 상단에 상시 배너를 띄운다.

- **비로그인 상태**: "체험판입니다 — 로그인하면 서버에 저장하고 계속 이어서 쓸 수 있어요" +
  [로그인하고 저장하기] 버튼
- **로그인 상태**: "이 선수 명단을 내 계정에 저장할 수 있어요" + [저장하기] 버튼
- 선수가 0명이면 버튼은 비활성화 (옮길 대상이 없으므로)

클릭 시:
1. 로그인이 안 되어 있으면 기존 로그인 플로우(카카오/이메일)를 그대로 실행하고, 로그인 완료 후
   자동으로 `/game-manager`로 돌아와 저장 모달을 띄운다.
2. 이미 로그인되어 있으면 바로 저장 모달을 띄운다.

모달은 "모임 이름" 한 항목만 입력받는다. 확인을 누르면:
- 새 `badminton_sessions` 행을 만든다 (이름=입력값, 장소="미정", 날짜=현재 시각, 나머지는 기존
  세션 생성 API의 기본값 그대로)
- 현재 game-manager의 선수 명단(이름/성별/급수/나이대)을 그 세션의 `guest_participants`로 복사한다
- `/badminton/{새 세션 id}`로 이동한다

## 마이그레이션 범위

- **옮기는 것**: 선수 명단(이름/성별/급수/나이대)만. `guest_participants`에 삽입. `guest_participants`의
  성별/급수/나이대 컬럼은 `NOT NULL`이므로, 로컬 선수 데이터에 값이 비어 있으면
  [useBoardRealtime의 addPlayer](../../../src/hooks/useBoardRealtime.ts)와 동일한 기본값 규칙을
  그대로 적용한다 (성별 미입력→`male`, 급수 미입력→`E`(0), 나이대 미입력→`20s`). 새 로직을 만들지
  않고 기존 규칙을 재사용한다.
- **옮기지 않는 것**: 참석 상태, 코트, 대기열, 진행 중/완료된 게임 기록. 새 세션은 전원 미참석
  상태로 깨끗하게 시작한다 (board_player_state는 [useBoardRealtime](../../../src/hooks/useBoardRealtime.ts)의
  기존 lazy-backfill 로직이 첫 로드 시 자동으로 만들어주므로 마이그레이션 코드에서 직접 만들 필요 없음).
- **localStorage**: 그대로 둔다. 지우지 않는다. `/game-manager`는 마이그레이션 이후에도 독립적인
  체험판으로 계속 존재한다 (이번 작업 범위에서는 `/game-manager` 제거를 하지 않는다).

## 로그인 왕복 처리

기존 로그인 흐름(`signInWithKakao`/`signInWithEmail` → `/auth/callback`)은 로그인 성공 시 항상
`/`로 리다이렉트한다 (`src/app/auth/callback/page.tsx:41`). "로그인 후 game-manager로 돌아와서
모달을 띄운다"를 지원하려면, 리다이렉트 대상을 조건부로 바꿔야 한다.

- 배너 클릭 시(비로그인 상태) `localStorage`에 `game-manager-pending-migration = 'true'` 플래그를
  남기고 로그인을 시작한다.
- `/auth/callback`은 로그인 성공 후 이 플래그가 있으면 `/game-manager`로, 없으면 기존처럼 `/`로
  리다이렉트한다. 플래그는 리다이렉트 직전에 지운다 (재방문 시 다시 뜨지 않도록).
- `/game-manager`는 마운트 시 이 플래그가 남아있는지 확인해 모달을 자동으로 연다 (플래그가 정상
  소비되지 않고 남아있는 예외 상황 대비 — 정상 흐름에서는 callback이 이미 지웠으므로 보통 없음).

이 변경은 game-manager 마이그레이션 플래그가 없는 모든 기존 로그인 시나리오(예: `/badminton/invite/[code]`에서
로그인 참가)에는 영향을 주지 않는다 — 플래그가 없으면 정확히 기존 동작(`/`로 이동)과 같다.

## 에러 처리

- 선수 0명: 버튼 비활성화로 애초에 막는다.
- 세션 생성 실패 또는 선수 복사 중 일부 실패: 토스트로 에러를 보여주고 중단한다. localStorage
  데이터는 그대로 보존되므로 사용자는 다시 시도할 수 있다. 부분 삽입(세션은 만들어졌는데 선수 복사가
  중간에 실패한 경우)은 그 세션을 삭제하지 않고 그대로 두며, 사용자가 `/badminton/[id]`에서 직접
  나머지 선수를 등록하거나 재시도할 수 있다 (자동 롤백은 범위 밖 — 실패 빈도가 낮고, 실패해도 그
  세션에서 수동으로 이어서 등록하면 되므로).

## 범위 밖

- `/game-manager` 제거 여부는 이번에 다루지 않는다 (실전 검증 이후 별도 결정).
- 코트/대기열/게임 기록 마이그레이션.
- localStorage 자동 정리.
- 로그인 리다이렉트 대상을 범용적으로 파라미터화하는 것 (이번엔 game-manager 전용 플래그로만 한정).
