# 참가자 정보 중복 정리 및 보드 데스크톱 레이아웃 개선

> `2026-08-10-spectator-board-design.md`(스펙테이터 현황판) 배포 직후 발견된 UX 문제를 다룬다.

## 배경

스펙테이터 현황판이 배포되면서 `/badminton/[id]`의 정보 구조가 다음과 같아졌다.

- 페이지 상단 `ParticipantsList` — 세션에 가입한 전원(참가자+게스트)을 이름·성별·급수·참가시각과
  함께 개별 카드로 나열. 모임장에게는 퇴장 버튼도 붙는다.
- 그 아래 역할별 보드
  - 모임장: `OrganizerBoard` 안의 "인원 풀"(`PlayerList`)이 **같은 사람들을** 출석·상태·필수포함
    등 보드 전용 정보와 함께 다시 나열한다.
  - 그 외 전원: `SpectatorBoard`는 "대기 중" 섹션에 *출석 처리되고 코트/대기열에 없는* 사람만
    보여준다. 결석·휴식 인원은 `ParticipantsList`가 유일한 노출 지점이다.

모임장 입장에서는 같은 명단을 상단(가입 정보)과 인원 풀(운영 정보)에서 두 번 스크롤하게 된다.
또한 `OrganizerBoard`는 7개 섹션이 아코디언으로 세로로만 쌓여 있어, PC/태블릿처럼 화면이 넓어도
자주 쓰는 "인원 풀"과 "코트 관리"를 보려면 계속 스크롤해야 한다.

## 목표

1. 참가자 상세 정보가 표시되는 곳을 역할당 한 곳으로 줄인다.
2. 참가자 목록은 항상 보이는 요약(정원·성별·급수 통계)으로 축소한다.
3. PC/태블릿(`md` 이상, 768px~)에서 좌우 2단 배치로 스크롤을 줄이되, 모바일은 기존 1단 유지.
4. `OrganizerBoard`의 "인원 풀"·"코트 관리", `SpectatorBoard`의 "코트 현황"은 접이식이 아니라
   항상 펼쳐진 상태로 고정한다 — 가장 자주 참조하는 정보이기 때문이다.

**비목표(명시적 제외):**
- DB 스키마 변경 없음. 이 작업은 기존 `session_participants`/`guest_participants`/
  `board_player_state`를 그대로 읽는 화면 레이어 재구성이다.
- `PlayerList`에 모임장(크라운) 표시나 참가 시각을 추가하지 않는다 — 게임 운영에 필수 정보가
  아니라는 판단.
- 모바일 레이아웃 자체의 재설계는 하지 않는다. 지금의 세로 1단 순서·아코디언 기본 열림/닫힘
  상태는 유지한다.

## 설계

### 1. `ParticipantsList` — 요약 카드로 축소

**Props 변경** — `creatorId`, `currentUserId`, `sessionId`, `onParticipantRemoved`를 제거하고
`participants`, `guestParticipants`, `maxParticipants`만 남긴다.

퇴장 기능은 안전하게 제거할 수 있다. `useBoardRealtime.removePlayer`가 이미 로그인 참가자는
`/api/badminton/sessions/remove-participant` 호출로, 게스트는 `guest_participants` 삭제로
동일하게 처리하고 있고, "인원 풀"은 board 스냅샷을 통해 세션의 모든 참가자·게스트를 빠짐없이
포함한다(`useBoardRealtime`의 `missingInserts`가 신규 참가자를 자동으로 `board_player_state`에
편입시킨다). 따라서 퇴장 기능을 인원 풀 하나로 합쳐도 기능 손실이 없다.

**유지** — 카드 헤더의 "참가자 현황 (n/max)", 성별·급수 통계 배지, 빈자리/미참가 안내 문구.
**제거** — 참가자·게스트 개별 행, 아바타, 참가시각, 퇴장 버튼, `removingId` 상태와
`removeParticipantApi` 호출 로직.

### 2. `page.tsx` 배선 정리

`<ParticipantsList>` 호출에서 제거된 props를 정리한다. `OrganizerBoard`/`SpectatorBoard`
호출부는 변경 없음(둘 다 `sessionId`만 받는 기존 구조 유지).

### 3. `OrganizerBoard` — 데스크톱 2단 레이아웃

`md` 이상에서 아래처럼 재배치한다. 모바일은 아래 DOM 순서 그대로 세로 1단 스택.

```
[md 이상]
┌─────────────────┬─────────────────┐
│  선수 등록 ▸ (기본 닫힘) │                 │
│   인원 풀          │   코트 관리        │   <- 항상 펼침, 접기 불가
│  (항상 펼침)        │  (항상 펼침)        │
├─────────────────┼─────────────────┤
│   팀 뽑기          │   대기열           │   <- 기존처럼 접이식(기본 열림)
└─────────────────┴─────────────────┘
[ 게임 기록 ▸ / 초기화 ▸ ]                   <- 접이식(기본 닫힘), 전체 폭

[모바일 (< md)]
선수 등록 → 인원 풀 → 코트 관리 → 팀 뽑기 → 대기열 → 게임 기록 → 초기화
(전부 세로 스택, 각 섹션의 기본 열림/닫힘 상태는 위와 동일)
```

- **"인원 풀"·"코트 관리"**: `Collapsible`/`CollapsibleTrigger` 래핑을 걷어내고 일반 `Card`로
  바꾼다 — 챕터가 아예 없으므로 접을 수 없다. `openSections` state에서 `playerList`,
  `courtManager` 키를 제거한다.
- **"팀 뽑기"·"대기열"**: 기존 `Collapsible` 동작 그대로, 위치만 인원 풀/코트 관리 아래 2단 행으로
  옮긴다.
- **"선수 등록"**: 왼쪽 컬럼에서 "인원 풀" 바로 위에 붙인다(접이식, 기본 닫힘 유지) — 등록 직후
  바로 아래 인원 풀에서 확인하는 흐름이라 모바일 세로 스택에서도 붙어 있어야 한다. 왼쪽 컬럼은
  "선수 등록 + 인원 풀"을 세로로 담고, 오른쪽 컬럼은 "코트 관리" 하나만 담는 구조가 된다.
- 2단 행은 `grid grid-cols-1 md:grid-cols-2 gap-3 items-start`로 구현해, 두 컬럼의 높이가
  달라도 서로 늘어나지 않게 한다.

### 4. `SpectatorBoard` — 전체 참가자 명단 추가 + 데스크톱 2단 레이아웃

**신규 섹션: "전체 참가자 명단"** — `ParticipantsList` 축소로 사라지는 결석/휴식 인원 노출을
대체한다. `useBoardSpectator`가 이미 전체 `players`를 반환하므로 훅 변경은 없다.

- 표시 필드: 이름, 성별 아이콘, 급수 배지, 연령대 배지(게스트만), 상태 배지(게임중/대기열/대기
  중/미참석 — `PlayerList`의 배지 의미를 읽기 전용으로 재사용).
- 액션 버튼 없음(읽기 전용). 이름 가나다순 정렬.
- 기본 접힘(`Collapsible`), "오늘 게임 기록" 섹션 바로 위에 배치.

**레이아웃**(`md` 이상):

```
[md 이상]
┌─────────────────┬─────────────────┐
│   코트 현황         │   대기열           │   <- 둘 다 항상 펼침(기존과 동일, 접기 기능 없었음)
│  (항상 펼침)        │   대기 중          │
│                  │  (세로로 쌓임)      │
└─────────────────┴─────────────────┘
[ 전체 참가자 명단 ▸ (기본 닫힘) ]
[ 오늘 게임 기록 ▸ (기본 닫힘) ]

[모바일 (< md)]
코트 현황 → 대기열 → 대기 중 → 전체 참가자 명단 → 게임 기록
(전부 세로 스택, 기존 순서 + 새 명단 섹션 추가)
```

- 왼쪽 컬럼: 코트 현황 하나만.
- 오른쪽 컬럼: 대기열 + 대기 중을 세로로 쌓는다(각각 지금처럼 별도 `Card`).
- 전체 참가자 명단·게임 기록은 2단 영역 아래 전체 폭에 접이식으로 배치.

## 엣지 케이스

- **참가자 0명** — `ParticipantsList` 요약 카드의 기존 빈 상태 문구를 그대로 사용.
- **전체 참가자 명단이 비어 있음(0명)** — "아직 참가자가 없습니다" 등 다른 섹션과 일관된 안내
  문구.
- **게스트 vs 로그인 참가자 구분** — `ParticipantsList` 축소로 사라지는 정보이므로, `player.
  participantType === 'guest'`일 때 급수 배지 옆에 "게스트" 배지를 새로 추가한다. `PlayerList`
  (인원 풀)와 신규 스펙테이터 명단 양쪽에 동일하게 적용해 두 화면의 표현을 맞춘다.
- **모임 종료(`status === 'completed'`)** — 기존처럼 두 보드 모두 렌더링되지 않고 안내 문구만
  보이므로 이번 변경과 무관.

## 검증

DB/스키마 변경이 없으므로 SQL 실행 단계는 없다. `pnpm dev` 수동 클릭 + `pnpm lint` / `pnpm build`.

1. **기능 손실 없음** — 모임장이 참가자 목록 축소 후에도 인원 풀에서 로그인 참가자·게스트 모두
   퇴장시킬 수 있는지 확인.
2. **데스크톱 레이아웃** — 브라우저 폭을 768px 전후로 오가며 `OrganizerBoard`/`SpectatorBoard`가
   1단 ↔ 2단으로 올바르게 전환되는지, 2단일 때 "인원 풀"/"코트 관리"/"코트 현황"에 접기 토글이
   없는지 확인.
3. **스펙테이터 명단 실시간 반영** — 모임장 화면에서 참석 체크·게임 배정을 바꾸고, 시크릿 창의
   "전체 참가자 명단"이 실시간으로 갱신되는지 확인.
4. **모바일 회귀** — 좁은 화면에서 두 보드 모두 새 순서(`OrganizerBoard`: 선수 등록 → 인원 풀 →
   코트 관리 → 팀 뽑기 → 대기열 → 게임 기록 → 초기화)로 보이는지 확인.

## 제약

- **DB는 additive-only** — 이번 작업은 스키마를 전혀 건드리지 않는다.
- **`git add` / `git commit`을 실행하지 않는다.** 파일 수정과 검증만 하고 스테이징·커밋은 사용자가
  직접 한다(`CLAUDE.md`의 Git Workflow 참고).
- **자동화 테스트를 새로 도입하지 않는다.**
